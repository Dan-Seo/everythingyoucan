# 작업 요약

앱 기능을 임의로 만들지 않고, 기존 아키텍처 지침을 실행 가능한 작은 템플릿으로 정리했어.

- 설계 문서와 재사용 가능한 스펙/역할 템플릿을 추가했어.
- 외부 패키지 없이 Python 표준 라이브러리로 검증 명령 실행기를 만들었어.
- 순서대로 테스트하고, 실패하면 멈추며, JSON 결과를 안전하게 교체해 저장해.
- 모든 결과에서 사람의 승인 상태는 pending으로 남겨. 자동 머지/배포는 없어.
- 실제 Opus 5.5가 작성한 것은 스키마 검증 함수야. 실행기 통합·테스트·문서는
  별도 오케스트레이션으로 작성하고 실행했어. 전부 Claude가 만들었다고 하지는 않아.
- 독립 검토에서 Git 메타데이터 덮어쓰기와 잘못된 Unicode 인자 문제를 찾아 고쳤어.

원래 CLAUDE.md와 .claude/settings.json은 그대로야. 기존 설정의 Windows 전용
보안 훅은 이 컴퓨터용으로 바꾸거나 우회하지 않았어. 사용 전에 별도 승인된 설정이 필요해.

실행: `python3 -m unittest discover -s tests -v`
전체 예제 검증: `python3 scripts/verify.py --config verification.json`

RESULTS.md에는 기준 SHA를 다시 고정한 뒤 실제로 실행한 3단계 검증 결과를 기록해.
독립 검증 1차 FAIL의 지적 사항별 처리 상태와 남은 한계는 REVIEW.md를 봐줘.
이 실행기는 샌드박스가 아니야. 신뢰할 수 있는 명령만 설정해서 사용해야 해.

ZIP만 풀면 Git 정보가 없으므로, 보고서 경로 검사를 사용하려면 새 폴더에서
git init을 먼저 실행해야 해. 기존 일반 파일은 Git 등록 여부와 관계없이 보호해.
줄 수 검사에는 코드가 들어 있는 기준 커밋도 필요해.
원본 체크아웃에는 별도 patch를 git apply로 적용할 수도 있어. 두 방법을 중복 적용하지 마.

아직 디블로팅을 하지 않았으므로 이 저장소는 최소 감축률 0%로 증가만 막아.
기준은 PM의 2차 수정 커밋 `912dd6af7e4a298a356eab47c65fe243244e88c8`로 다시 고정했어.
사용자가 수정 커밋을 기준으로 이후 증가를 막기로 결정했기 때문이야.
이번 안전성 수정으로 추가된 코드도 기준에 포함되므로, 코드가 줄었다는 뜻은 아니야.
실제 디블로팅을 시작하면 이 저장소 설정도 20%로 올려.
검사 스크립트의 기본값은 계속 20%야.
2차 수정에서는 다음 내용을 반영했어.

- Windows에서 `check_loc.py`와 시험 코드도 실행기와 같은 함수로 절대 PATH 항목에서 Git을 찾아.
- `.cmd`·`.bat` 실행 파일 경로는 공백이 없어도 항상 따옴표로 감싸서 구분자 때문에 다른 파일이 실행되지 않게 했어. 위험 문자나 제어 문자가 있는 경로와 인자는 계속 `launch_error`로 처리해.
- 보고서 접두사는 바이너리로 비교하고, 새 보고서는 UTF-8과 LF 줄바꿈으로 기록해. 이전 CRLF 보고서는 덮어쓰지 않으므로 새 경로를 지정하거나 기존 파일을 직접 옮기거나 지워야 해.
- `git grep -a`로 `.gitattributes`의 binary/`-diff` 속성이 코드 증가를 숨기지 못하게 했어. Git 실행·시간 초과·출력 디코딩 오류는 종료 코드 2로 처리해.
- 하이재킹 시험은 `NoDefaultCurrentDirectoryInExePath`를 제거한 환경에서 공격을 실행해. 3단계에서는 두 unittest 명령을 이 변수가 `1`인 환경과 제거된 환경에서 각각 실행해 기록해.
- 심볼릭 링크, 관문 실행 후 경로 재검사, 미추적 코드, 기준 0줄의 시험을 추가했고, 각 보호 코드를 제거한 사본에서 시험이 실패하는 것도 확인했어.

같은 LF 접두사를 쓰는 다른 JSON은 보고서와 구분할 수 없고, 경로 검사와 쓰기 사이의
경쟁 상태(TOCTOU)도 남아 있어. 3단계에서는 설정과 문서만 바꾸며 scripts/와 tests/는 수정하지 않아.
